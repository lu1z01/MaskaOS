# Política de segurança

Projeto em pré-alpha, **sem versões suportadas** até o primeiro release.

## Reportar uma vulnerabilidade

Não abra issue pública. Use o recurso de relatório privado de vulnerabilidades do repositório (GitHub *Security Advisories*) quando o repositório estiver publicado; até lá, contate o mantenedor diretamente. **Canal de contato a definir antes do primeiro release.**

Inclua: componente afetado, passos para reproduzir, impacto e versão/commit. Expectativa de resposta e prazo de divulgação serão definidos junto com o canal.

## Escopo

Configuração de build, scripts, módulos de instalação de ferramentas e artefatos publicados. Vulnerabilidades em software do Debian ou de terceiros devem ser reportadas ao respectivo projeto.

## Uso responsável

O sistema é destinado a auditorias autorizadas, laboratórios próprios e pesquisa. Não usamos nem aceitamos relatos que envolvam uso contra sistemas sem autorização.
